Cryptic Coach

A small model fine-tuned to answer cryptic crossword clues, with every stage scored on the same 3,000 clues whose answers it never saw in training. It solves 3.6% of them. This page shows how the project was built, why each choice was made, and what every experiment measured, including the ones that failed.

How it was built

The pipeline, phase by phase

One pinned prompt, one split and one scoring rule are shared by every stage, so any two rows in the results are comparable.

  2. Phase 2Eval harnessGreedy decoding, exact match, bootstrap CIs, test locked after one scoring.

Measuring honestly came first

Data and the answer-disjoint split

Cryptic setters reuse answers, so a random split lets a model score by remembering them. The headline split puts all clues for an answer on one side only, then checks for near-duplicates.

Phase 4

GRPO failed twice, then worked

GRPO only learns when some samples in a group beat the others. At 1% accuracy almost no group had a correct sample, and the model optimized whatever bonus was left.

Failed runs: dev accuracy by training step

Both runs start from the first SFT (1.8% on dev) and degrade. v1 had a length bonus; v2 had letter-position credit.

Working run: dev accuracy by cumulative step

From SFT v2 with dynamic sampling. A plateau for about 120 steps, then another point of gain.

The format collapse

Dev answer-tag rate in the working run. Groups with no right answer are discarded, so nothing penalized a missing tag. The fix keeps groups whose only contrast is format; it held for 111 re-run steps.

Phases 5 and 5b

A large model, and trying to learn from it

Same 300 clues, four models

Test subset, zero-shot with the pinned prompt. The API model is a reasoning model and 86 of 300 clues hit its token limit and count as wrong; of the 214 it finished, 93% were right. It may also have seen published puzzles.

Distillation: explanation arm minus its templated control

Paired difference in test accuracy, percentage points, 95% CI. Zero means no effect.

The student learned to write fluent wordplay that does not add up, then derived the answer from the invented working. Right-length answers fell from about 55% to about 25%. One design was tested: explanation before the answer, up to 3,699 examples, one learning rate. It does not show that distillation cannot work.

Phases 5 and 6

Export, demo and data hygiene

Local demo

A Gradio page sends the clue to a local llama-server running the 986 MB GGUF, with the pinned prompt and greedy decoding. It shows the raw output, the parsed answer and format checks (answer tag, letter count), plus an optional known-answer check. A banner says the model is usually wrong and that the definition line is a template.

Run it from a clean venv: pip install -r requirements-demo.txt, then python scripts/demo.py with the server and GGUF paths.

Data-hygiene test

The clues belong to newspapers and setters, so nothing derived from them may leave the machine. tests/test_data_hygiene.py collects every file git tracks or would track, normalizes the text, and fails if it contains any dev, test or random-split clue, any teacher wordplay line, or the train clues used for distillation. It also fails if clue-level or weight files sit outside the ignored data/, outputs/ and checkpoints/. A planted clue made it fail; the repository passes.

What went wrong

The definition is a template

Nothing in training checks that the answer follows from the clue.

Shaped rewards were gamed

The model wrote right-length non-words. Caught by reading samples and reporting exact match.

Explanations hurt

Teacher wordplay made students worse than their controls at both scales.

Format collapse

Dynamic sampling dropped the groups that would have penalized a missing tag.

Uneven comparison

The large model used thousands of thinking tokens; the small ones were capped at 256.

One seed

Results are single runs. The GRPO runs form one chain, not replicates.
