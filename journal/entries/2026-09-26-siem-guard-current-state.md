SIEM Guard reads security logs and flags suspicious activity. Raw ssh, http, ftp, dns and packages lines go through a parser (regex plus an LLM, qwen2.5:7b at temperature 0.1, schema-constrained) into parsed dicts; the behavioral detector (ssh/http/ftp, statistics) and the supply-chain detector (packages, fixed rules) then run with no LLM at all, and only the handful of flagged items reach the explaining model mistral:7b (temperature 0.5), which returns severity, reason and a next step before alerts are saved as JSON. Parsing and explaining are the only pipeline stages an LLM touches; detection is not.

Behavioral detection cuts each entity's (an IP, falling back to a username) events into windows of 5 events and summarizes each window as 8 numbers: `failed_login_ratio`, `login_frequency` (events per hour of the window's span), `unique_users`, `unique_ports`, `connection_duration_mean`, `bytes_transferred_mean`, `geographic_changes`, `off_hours_activity`. One population isolation forest of 200 trees (each tree a random subsample of at most 256 points, `max_samples=min(n, 256)`) flags any score above 0.6 (`anomaly_threshold`), and an entity with 3 or more windows (11+ events) also gets its own forest. Before the population branch is trusted, a median/MAD gate requires two or more features to exceed a modified z-score of 3.5 — `0.6745 * |x - median| / MAD`, `MIN_CORROBORATING_FEATURES` — so a single typo'd login is not an alert. Supply chain is four weighted rules: typosquat by edit distance to ~106 known packages (0.30), a rare source seen fewer than twice (0.20), a size jump beyond mean + 2 std (0.25), off-hours installs (0.15); a package is flagged at 0.4 or more.

Sessions 43 and 44 fixed the detector layer before anything measured the parser: real-format values (`'-'`, `'1.8 MB'`, Apache/ctime/BIND timestamps) used to crash the detectors and read as zero recall, and a detector exception now lands in `results['errors']` instead of being indistinguishable from "0 alerts". Calibration then dropped the entity tier after measuring that it added 0 recall in 120 trials (`history`-shape false-positive rate 100% -> 0.00-0.99%; the 50,000-forest `fit()` went 1,551s/4.06GB -> 0.8s/3MB), cut the ssh corroboration-gate leak from 1.6-2.2% to 0.00% (0.003% at 50k) with recall unchanged at 1.00, and memoized `get_feature_importance` (46.1ms -> 8.0ms). Sessions 45-48 built `rule_parser.py`, a strict, `fullmatch`-only rule registry for the known ssh/http/ftp/dns/packages formats, routed only unmatched lines to the LLM, and finally flipped the default to hybrid. On the three corpora parsing accuracy went 99.5% -> 100% (validation), 99.96% -> 100% (generalization) and 92.47% -> 100% (real-format), LLM parsing calls fell 21/26/100 -> 0/0/2, wall clock 450.5s/568.8s/978.2s -> 157.6s/252.4s/203.3s, and the rule parser held 96,000-98,000 lines/s flat from 50k to 500k lines against a ~1 line/s LLM path (~19.3h/50k, extrapolated, not run). A 10-novel-format, 300-line probe produced 0 false rule claims and 74-100% fallback accuracy on 9 of 10 formats, and the shadow audit (812 lines, 82 disagreements) found the rule path right on all 82.

Sessions 49-51 evaluated SemIf against the existing Ollama decision calls. Severity went 0.244 -> 0.602 macro-F1 and was adopted, wired behind `SIEM_GUARD_DECISION_BACKEND=semif` and off by default; status classification (0.783 -> 0.956 accuracy, Brier 0.067, 5s median latency) and format routing (0.911 -> 0.930) were recommended but left unwired for want of a call site; supply-chain action was not adopted because all three arms missed every `block`-labeled case. Session 52 decided the supply-chain and status questions: the size anomaly now tests any event against the median/robust spread of the others rather than only the last event, an npm known-package list was added, typosquat-alone was left at 0.3 below the 0.4 threshold with measured FP evidence (2.16%/1.57%), and http 401/403 now count as failed logins with 404 deliberately excluded — real-format supply-chain oracle F1 went 0.5 -> 0.909. Session 53 closed the arc: the ledger audit ended 19 closed, 3 carried, 3 not planned of 25 rows, `git status` was clean at the start (a first for a synthesis session in this project), and the full suite stood at 559 passed, unchanged from Session 52.

Loose ends, from the plan's ledger after the Session 53 audit (19 closed, 3 carried, 3 not planned of 25 rows):

- **Carried — PAM pseudo-entities.** `alice`/`ken`/`unknown` pseudo-entities from session-lifecycle lines with no `src_ip`: Session 45 built the parser-side pid/host linkage (45/45 lines linkable on its corpus) but deliberately did not wire it into `BehavioralDetector._get_entity`, so the symptom Session 40 found still occurs live.
- **Carried — ssh `user`/`status` over-nulling in the LLM fallback path.** Confirmed live at volume by Session 48's shadow audit (all 82 disagreements were rule-right), root-caused by Session 47 to the nullable-schema trade between under- and over-reporting fields a line visibly carries; only reachable via the shrinking fallback path.
- **Carried — SemIf severity's live state-shape mismatch.** Wired and shipped behind a flag, but Session 50's 0.244 -> 0.602 improvement was measured on a different state shape than the `anomaly_dict` the live call site actually sends.
- **Not planned — reasoning-text grounding metric.** Session 50 scored severity classification against engineered labels, not free-text reasoning quality; no session built one.
- **Not planned — MITRE stubs.** 13/15 techniques remain RNG stubs (2 of 15 with real detection logic) — a closed product-scope decision, restated so nobody re-opens it.
- **Not planned — adversarial wall-clock tripwire.** Catalog is still 15 techniques; unchanged.

Closed (19): the Session 43 detector-input items (exception surfacing, `coerce_number` on `'-'`/unit-suffixed sizes, the three added timestamp formats, `_verify_model` reading `m['model']`); the Session 44 calibration items (entity-tier FP, the tier's measured purpose and the 50,000-forest cost, the ssh gate leak, `get_feature_importance` cost); Session 40's real-format fixes B1/B2/C1/D1 and the pip/npm packages pre-pass C2; the real-format `RegexLogParser.PATTERNS` item, superseded by `RuleLogParser` (the old parser kept untouched as the comparison baseline); the Session 52 supply-chain E1 items and the http `status_code`/ftp `FAIL` status signal; the `generate_evasion_variants` refusal leak; parsing-at-scale throughput; the recurring uncommitted-docs item (closed this time); the Session 41-vs-42-vs-44 numbering/supersession question; and the SSH residual ~9pp parsing gap, now moot under the hybrid's 100% ssh accuracy on every corpus.
